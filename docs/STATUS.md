# OpenPlan Studio — avancement

Dernière mise à jour : 24 septembre 2026. Ce fichier est la source de vérité côté code ; la
page Notion « OpenPlan » (tenue par la session PO) en reprend l'avancement à chaque incrément.

## En une phrase

Le vertical slice 0.1 est fonctionnel de bout en bout, **photo comprise** : importer une
photo (elle reste sur la machine, EXIF retiré), obtenir une proposition de pièce
rectangulaire estimée, la corriger, calibrer sur une longueur connue, voir le plan 2D coté et
la scène 3D, exporter SVG, JSON, GLB et (avec Blender) `.blend` + rendu. La détection est
heuristique (lignes et points de fuite) : elle donne un point de départ, pas un relevé.

## Ce qui marche aujourd'hui (démo en 5 minutes)

```bash
cd ~/plandesign
make start      # construit le front et sert tout sur http://localhost:8000/ (un terminal, un lien)
# depuis Windows : double-clic sur start-openplan.cmd, ou
# wsl -d Debian -- bash -lc "cd ~/plandesign && make start"
# en développement : make api (terminal 1) + make dev (terminal 2, http://127.0.0.1:5173)
```

Parcours guidé pour non-développeur (photo du grenier → combles → PDF) :
[docs/guide/premier-essai.md](guide/premier-essai.md).

0. (Optionnel) Panneau **Photos** : importer une photo de la pièce, saisir la hauteur de prise
   de vue, **Proposer un plan depuis la photo** : quatre murs apparaissent (deux estimés en
   pointillé, deux inférés), la caméra estimée aussi ; le calque de superposition montre les
   lignes retenues. Corriger les murs en les glissant, puis passer à l'étape 3.
1. Sinon : outil **Mur** (W), cliquer quatre coins, Échap.
2. **Détecter les pièces** : la pièce, son sol et son plafond apparaissent, surface affichée.
3. Outil **Porte** (D) ou **Fenêtre** (F), cliquer sur un mur.
4. Sélectionner un mur, saisir sa longueur réelle, **Calibrer** : tout le plan est mis à l'échelle,
   le mur passe en « mesuré » (vert), les autres restent « estimés » (pointillé, ≈).
5. Vue **Plan + 3D**, puis panneau Blender : `.blend`, GLB et aperçu rendu.
6. Exports SVG, GLB, JSON dans la barre d'outils.

En ligne de commande, le même enchaînement sans interface :

```bash
uv run openplan run tests/fixtures/rect_room/image.png --out out/demo --measure 3.85 --camera-height 1.4
```

## Assistant IA (Gemini, ChatGPT, modèle local) — cadrage

Objectif exprimé : brancher un modèle du type Gemini ou ChatGPT pour que « le résultat soit
super ». Le brief le prévoit (section 14) et le cadre : **l'IA propose, l'utilisateur valide ;
aucune donnée ne part vers un service distant sans consentement explicite.**

Trois rôles possibles, du moins risqué au plus ambitieux :

| Rôle | Ce que le modèle reçoit | Ce qu'il renvoie | Version |
|---|---|---|---|
| **Intention** : transformer un brief en langage naturel en contraintes structurées (`room_type`, objets requis, style, à conserver, à éviter, budget) | Texte seulement, jamais d'image | JSON validé par Pydantic ; refusé s'il invente une dimension | 0.3 |
| **Critique** : relire une variante d'aménagement (remarques citant meuble + règle, importance, action proposée) | Texte seulement : description de la pièce, brief, meubles et distances aux repères, remarques des règles ; jamais d'image | JSON validé ; meuble inconnu écarté, règle hors liste → « autre », position proposée ignorée ; jamais appliqué (action = variante révisée à relire) | 0.3 |
| **Critique et suggestions** : commenter une proposition d'aménagement validée par le moteur de contraintes | Le JSON de la scène (pas l'image), en mètres | Texte + suggestions structurées | 0.3 |
| **Perception** : estimer murs, ouvertures, proportions à partir de la photo (modèle vision, ex. Gemini) | **La photo**, EXIF retiré, après consentement explicite par projet | Éléments `DetectedElement` avec score, marqués `estimated`/`observed` | 0.1.x, opt-in |

Principes d'implémentation :

- un protocole `LanguageModel` / `VisionLanguageModel` dans `openplan/adapters`, avec trois
  implémentations interchangeables : API compatible OpenAI (ChatGPT, mais aussi Gemini via son
  point d'entrée compatible, et les serveurs locaux Ollama / llama.cpp), API Gemini native, et
  un modèle local par défaut ;
- clés dans `.env` (`OPENAI_API_KEY`, `GEMINI_API_KEY`), jamais commitées ; `privacy.allow_remote_models`
  doit être `true` **et** l'utilisateur doit confirmer par projet avant le premier envoi ;
- chaque appel réseau est journalisé (quoi, vers où, combien d'octets) sans le contenu ;
- les sorties du modèle sont des propositions `generated` : elles n'écrasent jamais une mesure ;
- documentation dans le registre de modèles avec `remote: true`, conditions d'utilisation et coût.

Ordre recommandé : d'abord l'incrément 5 (sans IA distante, pour avoir la chaîne image → plan),
puis le rôle « Perception » en opt-in comme second détecteur, puis « Intention » avec la 0.3.
